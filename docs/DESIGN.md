## ภาพรวม

เอกสารนี้สรุป **กฎของระบบ** เกมปลูกผักแนว life-sim จากการศึกษา Harvest Moon: Back to Nature (PS1) เพื่อใช้เป็นจุดตั้งต้นออกแบบเกมของเราเอง ทุกข้อมาจากโค้ดเกมหรือการวัดใน BizHawk (บันทึกละเอียดอยู่ใน NOTES.md ของโปรเจกต์)

ตัวเลขในคอลัมน์ "ค่าใน HM" มีไว้อ้างอิงว่าเกมต้นแบบตั้งไว้เท่าไร เกมของเราควรปรับเองให้เข้ากับจังหวะเกมที่ต้องการ

**กฎ clean-room** ที่ใช้ตลอดเอกสาร:

- **เอามาได้**: กลไก กฎ วงจรการเล่น และแนวคิดการออกแบบ
- **ต้องทำใหม่**: โค้ด (เขียนเองจากเอกสารนี้ ไม่ลอกจาก decompile) ภาพ เพลง เสียง ตัวละคร ชื่อ เนื้อเรื่อง บทพูด และตัวเลขสมดุล
- **ห้ามใช้**: ชื่อ Harvest Moon / Back to Nature และไฟล์ใด ๆ จากแผ่นเกม

## ระบบเวลา

เวลาเดินตลอดเมื่ออยู่ข้างนอก และเป็นแรงกดดันหลักของเกม ผู้เล่นมีเวลาจำกัดต่อวัน จึงต้องเลือกว่าจะใช้วันนั้นทำอะไร

| กฎ | ค่าใน HM | ข้อเสนอสำหรับเกมเรา |
| --- | --- | --- |
| ความเร็วนาฬิกา | 1 นาทีในเกม = 0.5 วินาทีจริง (24 ชั่วโมงในเกม = 12 นาทีจริงถ้าอยู่ข้างนอกตลอด) | ปรับได้ตามความยาวที่อยากให้ 1 วัน |
| เวลาหยุด | ในอาคารทุกแห่ง และระหว่าง event บางตัว | เก็บไว้ ทำให้ผู้เล่นไม่รีบเวลาคุย/ซื้อของ |
| วันเปลี่ยน | ตอน 6:00 ไม่ใช่เที่ยงคืน | ทำให้ "หนึ่งวัน" ตรงกับรอบตื่น-นอน |
| ปฏิทิน | 4 ฤดู × 30 วัน, มีวันในสัปดาห์ | ฤดูสั้นลง (เช่น 28 วัน) ช่วยให้เปลี่ยนฤดูเร็วขึ้น |
| ช่วงแสง | เช้า 5–6, กลางวัน 7–14, เย็น 15–16, กลางคืน 17–4 | ใช้ tint ทั้งจอ ค่อย ๆ เปลี่ยนสีเมื่อเข้าช่วงใหม่ |

**ตารางงานตามเวลา (time schedule)** คือหัวใจของระบบ เกมเช็คทุกนาทีว่าตรงกับรายการไหน แล้วส่งงานเข้าคิว:

- ทุกชั่วโมง: อัปเดตสัตว์และชาวบ้าน
- 17:58: นับเงินจากกล่องส่งของ
- 6:00 ทุกวัน: สิ้นวัน (อากาศ พืชโต ผลของฝน/พายุ ย้ายผู้เล่นกลับบ้าน) ไม่ว่าจะนอนหรือไม่
- วันแรกของฤดู: เปลี่ยนตารางพืชและภาพประจำฤดู
- วันสิ้นฤดู: สรุปบัญชีรายรับรายจ่าย

โครงสร้างนี้ดีมากสำหรับเกมเรา: งานทุกอย่างที่ผูกกับเวลาเป็นแค่ข้อมูลในตาราง (ปี ฤดู วัน ชั่วโมง นาที → งาน) เพิ่มของใหม่ได้โดยไม่แตะโค้ด

## อากาศ

อากาศของ "พรุ่งนี้" ถูกสุ่มไว้ล่วงหน้าหนึ่งวัน ผู้เล่นจึงดูพยากรณ์ทาง TV แล้ววางแผนได้ ตอนสิ้นวัน ค่าพรุ่งนี้จะกลายเป็นวันนี้

| ฤดู | กฎสุ่มใน HM |
| --- | --- |
| ใบไม้ผลิ | ฝนประมาณ 1 ใน 3 วัน |
| ร้อน | พายุไต้ฝุ่น 1/20, ฝน 1/20 |
| ใบไม้ร่วง | ฝน 1/5 |
| หนาว | พายุหิมะ 1/10, หิมะประมาณครึ่งหนึ่งของวัน |

**ข้อยกเว้น**: วันเทศกาลและวันเกิดของตัวละครหลักแดดออกเสมอ และพายุจะลดเป็นฝน/หิมะถ้าวันถัดไปเป็นเทศกาล

**ผลต่อฟาร์ม** (ตอนสิ้นวัน):

- ฝน: รดน้ำแปลงทั้งหมดให้อัตโนมัติ ถือเป็นวันพักของผู้เล่น
- หิมะ: ปกคลุมแปลง
- ไต้ฝุ่น / พายุหิมะ: ทำลายพืชบางส่วนและโรงเรือน วางหินและกิ่งไม้ใหม่ในแปลง

สำหรับเกมเรา ให้แยก "การสุ่มอากาศ" กับ "ผลต่อฟาร์ม" ออกจากกัน แล้วกำหนดโอกาสต่อฤดูไว้ในไฟล์ข้อมูล จะปรับสมดุลได้ง่าย

## ฟาร์ม

ฟาร์มเป็นกริดช่องสี่เหลี่ยม (ใน HM ขนาด 45 × 25 ช่อง และโรงเรือน 7 × 7) ทุกช่องเก็บข้อมูลเพียงไม่กี่อย่าง แล้วระบบทั้งหมดอ่าน/เขียนข้อมูลชุดนี้

| ข้อมูลในช่อง | ความหมาย |
| --- | --- |
| ของบนช่อง | ว่าง / หิน / กิ่งไม้ / วัชพืช / ตอไม้ / พืชชนิดไหน |
| ดิน | ยังไม่ไถ / ไถแล้ว / ไถแล้วรดน้ำ / หว่านแล้ว / หว่านแล้วรดน้ำ |
| ขั้นการโต | 0 = เมล็ด ไปจนถึงขั้นสุก |
| จำนวนวันในขั้นนี้ | นับเฉพาะวันที่ได้รดน้ำ |

**เครื่องมือห้าอย่าง** แต่ละอย่างมี 5 ระดับ กดค้างเพื่อชาร์จได้ตามระดับเครื่องมือ ชาร์จมากขึ้น = ทำงานได้หลายช่องขึ้น แต่เสีย stamina มากขึ้น

| เครื่องมือ | ทำอะไร | จำนวนช่องต่อการชาร์จ 0–4 (HM) |
| --- | --- | --- |
| จอบ | ไถดิน | 1, 2, 3, 4, 6 (เป็นแนวตรงไปข้างหน้า) |
| บัวรดน้ำ | รดน้ำ เติมที่บ่อ | 1, 3, 6, 9, 15 ใช้น้ำตามจำนวนช่อง |
| เคียว | ตัดวัชพืช / หญ้า (ได้อาหารสัตว์) | 1, 3, 6, 9, 25 |
| ขวาน | ผ่ากิ่งไม้/ตอไม้ (ได้ไม้) | ทีละช่อง ตอใหญ่ต้องตี 12 ครั้ง + ขวานระดับ 1 |
| ค้อน | ทุบหิน | ทีละช่อง หินใหญ่ต้องตี 6 ครั้ง + ค้อนระดับ 1 |

การตีสะสมได้เมื่อยืนอยู่กับที่ เดินหรือเปิดเมนูจะรีเซ็ต ชาร์จค้างนานเกินไป (60 tick) จะกลายเป็นท่า over-charge ที่เสียเวลาเปล่า ใช้เครื่องมือแต่ละครั้งได้ค่าประสบการณ์ (ทำงานสำเร็จได้มากกว่าตีพลาด)

**การหว่าน**: ถุงเมล็ด 1 ถุงหว่าน 3 × 3 ช่องรอบตัวผู้เล่น ลงเฉพาะช่องที่ไถแล้ว ทำให้ผู้เล่นวางแปลงเป็นบล็อก 3 × 3 เว้นทางเดินตรงกลาง เป็นการออกแบบที่น่าเอามาใช้

**การโต (ตอนสิ้นวัน ทีละช่อง)**:

1. ช่องว่างสุ่มเกิดวัชพืช (ใบไม้ผลิ/ร่วง 1/128, ร้อน 1/64, หนาวไม่เกิด)
2. พืชผิดฤดู ตายทันที (เหี่ยว) หนาวล้างแปลงกลับเป็นดินไถ
3. ถ้ารดน้ำแล้วและยังไม่สุก: วันในขั้น + 1 ครบจำนวนวันของขั้น → ขึ้นขั้นถัดไป
4. ดินแห้งทุกช่อง (ต้องรดใหม่ทุกวัน)

พืชแต่ละชนิดเป็นแค่ระเบียน 1 แถว: ฤดูที่ปลูกได้, จำนวนวันของแต่ละขั้น, ขั้นสุก, ขั้นที่กลับไปหลังเก็บ (พืชเก็บซ้ำได้) และผลผลิตที่ได้ เช่น ใน HM พืชหัวเก็บได้ครั้งเดียว ส่วนแตงกวาและสตรอเบอรี่เก็บซ้ำได้ เพิ่มพืชใหม่ = เพิ่มแถวข้อมูล

**พายุ**: ทุกช่องที่มีพืชมีโอกาสพัง 1/16 โรงเรือนมีโอกาสพัง 31% ต่อคืนพายุ (เป็นความเสี่ยงที่ทำให้ผู้เล่นต้องคอยดูพยากรณ์)

## เศรษฐกิจขั้นต้น

การขายทำผ่าน **กล่องส่งของ** ไม่ใช่การต่อรองกับพ่อค้า เงินเข้าตอน 17:58 วันละครั้ง

- โยนของลงกล่อง: ราคาต่อชิ้นของไอเท็มนั้นบวกเข้ายอดในกล่องทันที พร้อมนับ "จำนวนที่เคยส่ง" ต่อชนิด (ใช้ปลดล็อกสิ่งต่าง ๆ ได้)
- วันเทศกาลไม่มีการจ่าย ยอดค้างไว้จ่ายวันถัดไป
- บัญชีเก็บรายรับ/รายจ่ายย้อนหลัง 4 ฤดู
- เงินเริ่มต้น 500 G สูงสุด 9,999,999 G
- ตะกร้า (ซื้อได้): ใส่ของได้ 30 ชิ้น ถือไปส่งทีเดียว ลดการเดินไปกลับ

ข้อดีของระบบนี้คือเรียบง่ายและทำให้ "เย็นนี้จะได้เงิน" เป็นเป้าหมายประจำวัน ประเด็นที่เกมเราอาจต่อยอด: ราคาตามคุณภาพผลผลิต หรือราคาที่ขึ้นลงตามฤดู

**เป้าหมายสัปดาห์แรก (ของเกมเราเอง):** เริ่มเกมด้วย 500 G แต่ไก่ราคา 1,400 G วัว 6,000 G ช่วงแรกจึงมีแค่ "รดน้ำแล้วรอ" ยายโทเมะจึงให้ "รายการงานสัปดาห์แรก" ในฉากเปิดเกม เป้าหมายเล็ก ๆ ทำได้ภายในวันที่ 1-3 (ปลูก 9 แปลง ทักทายชาวบ้าน 3 คน เก็บของป่า 4 ชิ้น ตกปลา 1 ตัว) และตลอดสัปดาห์ (ส่งพืช 5 ชิ้น หาเงินจากกล่องส่งของให้ครบ 1,000 G) แต่ละข้อมีรางวัลที่เห็นได้ทันที (เงิน เมล็ด ข้าวปั้น ลูกเจี๊ยบ) และโน้ตขอบคุณจากชาวบ้าน HUD แสดงเป้าหมายถัดไปใต้นาฬิกา ข้อมูลทั้งหมดอยู่ใน data/goals.json

## ผู้เล่น

ผู้เล่นมีค่าพลังสองตัวที่ทำงานต่างกัน: **stamina** หมดเร็วแต่ฟื้นง่าย ส่วน **fatigue** สะสมช้า และลงได้ด้วยการนอนเท่านั้น

| ค่า | ลด / เพิ่มเมื่อ (HM) |
| --- | --- |
| Stamina (เต็ม 100 เพิ่มได้ด้วยผลไม้พิเศษ) | ใช้เครื่องมือ −1 ถึง −5 ตามระดับชาร์จ · กิน/ดื่ม + ตามอาหาร · นอน +7 ต่อชั่วโมง + 50 |
| Fatigue (0–100) | ใช้เครื่องมือ +1 ตอนฝนตก / 22:00–23:59 / stamina 0, +2 หลังเที่ยงคืน · ตื่นอยู่ตอนดึก +3 ถึง +10 ต่อ 2 ชั่วโมง · นอน −2 ต่อชั่วโมง −5 |

**สัญญาณเตือน**: เมื่อ stamina ต่ำกว่า 50%, 30%, 10% และเมื่อเหลือ 0 ตัวละครเล่นท่าเหนื่อย (ครั้งเดียวต่อเกณฑ์) fatigue 50 และ 80 ก็มีท่าของตัวเอง ผู้เล่นรู้สถานะได้โดยไม่ต้องมีแถบ HUD

**การล้ม**: fatigue ถึง 100 → หมดสติ ตื่นที่คลินิก เสียค่ารักษา 10 G แล้วตื่นอีกทีตอน 12:00 ของวันถัดไป (เสียเช้าไปครึ่งวัน) เป็นบทลงโทษที่เจ็บแต่ไม่ทำให้เกมจบ

**การนอน**: นอนเมื่อไหร่ก็ได้ เวลาข้ามไป 6:00 แต่ถ้า fatigue สูงจะตื่นสาย: ต่ำกว่า 50 ตื่น 6:00, 50–69 ตื่น 8:00, 70–79 ตื่น 10:00, 80–99 ตื่น 12:00 ไม่นอนเลยจนถึง 6:00 จะถูกย้ายกลับบ้านและ fatigue +10

**การกิน**: ไอเท็มทุกชิ้นเก็บผลเป็นตัวเลขสามตัว (stamina, fatigue, อื่น ๆ) เช่น ผักดิบ +3 / −1, เครื่องดื่มบางตัว +50 / −1 มีไอเท็มพิเศษที่เพิ่ม stamina สูงสุด และที่ลด fatigue จากเครื่องมือลงครึ่งหนึ่ง (ทั้งวัน)

## ชาวบ้าน

ชาวบ้านทุกคนเดินตาม **ตารางประจำวัน** ที่เลือกใหม่ทุกเช้า ผู้เล่นจึงเรียนรู้ได้ว่าใครอยู่ที่ไหนเมื่อไหร่ (ใน HM มี 37 คน และ 166 ตาราง)

**การเลือกตาราง** (ทุกเช้า): แต่ละคนมีรายการกฎ "ถ้าเงื่อนไขเหล่านี้จริงทั้งหมด → ใช้ตาราง X" กฎแรกที่ตรงชนะ ไม่มีกฎไหนตรงก็ใช้ตาราง default เงื่อนไขที่ใช้: วันในสัปดาห์ อากาศวันนี้ ฤดู วันเทศกาล วันเกิด และ flag ของเนื้อเรื่อง

**ตารางหนึ่งวัน** = สูงสุด 30 รายการ {เวลาเริ่ม, แผนที่, เส้นทาง} แต่ละเส้นทางเป็นคำสั่งสั้น ๆ เช่น ยืน, เดินไปจุด (x, z), รอ n tick, เปิดประตู, วนกลับ

- ถ้าผู้เล่นเข้าแผนที่กลางทาง เกม "เร่ง" ชาวบ้านไปตำแหน่งที่ควรอยู่ตามเวลาที่ผ่านไป (catch-up) ไม่ต้องจำลองทุกแผนที่ตลอดเวลา
- ผู้เล่นเดินชน → ชาวบ้านหยุดรอ เวลาที่หยุดสะสมเป็น "delay" (สูงสุด 30 นาที) ทำให้ตารางทั้งวันเลื่อนออกไป รีเซ็ตตอน 12:00 และ 18:00
- ผิวปากเรียก: ชาวบ้านหันมามองด้วยโอกาสขึ้นกับค่าความรัก (อารมณ์เล็ก ๆ ที่ทำให้รู้สึกว่าเขาจำเราได้)

**ร้านและประตู**: ประตูแต่ละบานมีเจ้าของและกฎปิด เช่น เปิด 9–17, ปิดวันอาทิตย์, ปิดเมื่อเจ้าของไม่อยู่บ้าน บ้านคนที่เราสนิทมากขึ้นจะให้เข้าได้นานขึ้น (10–18 → 8–20 → 6–22)

## Event และบทพูด

ทุกฉากเนื้อเรื่องเป็น **script เล็ก ๆ** ที่เก็บเป็นข้อมูล ไม่ใช่โค้ด ใน HM มี 451 event รันบน VM ที่มี 113 คำสั่ง

**รูปแบบ script**: รายการคำสั่ง แต่ละคำสั่งมี {คำสั่ง, ค่า 4 ตัว, ไปที่ไหนถ้าจริง, ไปที่ไหนถ้าเท็จ} แค่นี้ก็ทำทั้งลำดับ เงื่อนไข และการรอได้ (คำสั่งรอวนกลับมาตัวเองจนกว่าจะจริง)

คำสั่งหลักที่เกมเราควรมี:

- ตัวละคร: วาง เดิน/วิ่งไปจุด หันหน้า เล่นท่า ซ่อน/แสดง
- บทพูด: แสดงข้อความ ตัวเลือก yes/no หรือหลายตัวเลือก (ผลเก็บในตัวแปร)
- โลก: เปลี่ยนแผนที่ เลื่อนกล้อง fade เปิดประตู
- สถานะ: อ่าน/เขียน flag ตัวแปร ค่าความรัก เงิน ให้/รับไอเท็ม
- ควบคุม: รอ n tick ต่อ event ถัดไป คืนการควบคุมให้ผู้เล่นระหว่าง event

**เงื่อนไขเริ่ม event**: แต่ละแผนที่มีตารางเงื่อนไข (ช่วงเวลา, วัน, อากาศ, ค่าความรัก, flag, เคยดูแล้วหรือยัง) ตรวจเมื่อมี "เหตุ" เช่น เข้าแผนที่ นาทีผ่านไป คุยกับชาวบ้าน สำรวจจุดใดจุดหนึ่ง แถวแรกที่ตรงคือ event ที่เล่น (ลำดับในตาราง = ความสำคัญ)

**กล่องข้อความ**: ตัวอักษรขึ้นทีละตัว 4 บรรทัดต่อหน้า มีรูปหน้าผู้พูด ตัวแปรชื่อ (ชื่อผู้เล่น ชื่อฟาร์ม) และหัวใจบอกค่าความรัก

ข้อเสนอ: ทำ script เป็นไฟล์ที่คนอ่านได้ (เช่น JSON, YAML หรือ Ink/Yarn Spinner) แทนไบนารีแบบ HM คนเขียนเนื้อเรื่องจะทำงานได้เองโดยไม่ต้องแตะโค้ด

## ไอเท็มในโลก

ไอเท็มเป็น **ของจริงในโลก** ที่ถือ วาง และโยนได้ ไม่ใช่แค่ตัวเลขในกระเป๋า นี่คือเสน่ห์สำคัญของเกมนี้

- **มือสองข้าง**: มือเครื่องมือ 1 ช่อง และมือถือของ 1 ช่อง (ถือเหนือหัว) สลับกับกระเป๋าด้วยปุ่ม R1 / R2
- **กระเป๋า + ที่เก็บของ** (กล่องเครื่องมือ ตู้เย็น ตู้เก็บของ) กระเป๋าอัปเกรดได้ในร้าน
- **X**: หยิบ / วาง / โยน ของที่โยนตกน้ำจะหาย ตกกล่องส่งของจะขาย
- **ของป่า (forage)**: ตำแหน่งตายตัวต่อพื้นที่ ชนิดเปลี่ยนตามฤดู เก็บแล้วกลับมาใหม่หลังผ่านไปหนึ่งคืน (ใน HM มี 197 จุด) ให้เหตุผลในการออกสำรวจทุกวัน

**การตกปลา** เป็น mini-game ที่เรียบง่าย: เหวี่ยงเบ็ดลงน้ำ กดค้างรอ เมื่อปลากินเหยื่อมีเวลาสั้น ๆ ให้ปล่อยปุ่ม ปล่อยช้าไปปลาหนี

| กฎ | ค่าใน HM |
| --- | --- |
| เวลารอปลากิน | ขึ้นกับจุดและช่วงเวลา: กลางคืน/เช้ามืดเร็วสุด, กลางวันช้าสุด |
| โอกาสกินเหยื่อ | 20% ต่อรอบเช็ค (40% กับเบ็ดดี) |
| สิ่งที่ได้ | ตารางเปอร์เซ็นต์ต่อจุดตกปลา (ทะเลมีตารางต่อฤดู) |
| ปลาหายาก | ได้ครั้งเดียว มีเงื่อนไข เช่น หลัง 22:00 หรือหลังครบเควส |
| กันดวงซวย | ไม่ได้ปลาติดกัน 11 ครั้ง → ครั้งที่ 12 ได้ปลาแน่นอน |

กฎ "กันดวงซวย" แบบนี้ (pity timer) น่าเอาไปใช้กับทุกระบบสุ่มของเกมเรา

## สิ่งที่ยังต้องศึกษาและข้อเสนอ

**สัตว์** เพิ่งถอดกฎได้บางส่วน (งานของ milestone 6 ยังทำอยู่) โครงที่เห็นแล้ว:

- สัตว์ทุกตัวมีค่าความสุข 0–255 เริ่ม 10 อายุ (วัน/ปี) และวันเกิด
- ได้กินวันนี้ → +10 / ไม่ได้กิน → −10 ถึง −20 ตอนสิ้นวัน ออกไปกินหญ้าข้างนอกเกิน 4 ชั่วโมงก็นับเป็นอิ่ม ทิ้งไว้ตอนฝนตกความสุข −5 ต่อชั่วโมง
- ความสุขเป็น 0 → มีโอกาสป่วย ป่วยนานขึ้นโอกาสตายสูงขึ้น รักษาด้วยยา
- ผลผลิต (ไข่ นม ขนแกะ) มี 3 เกรดตามความสุข (ต่ำกว่า 100 / ต่ำกว่า 200 / สูงกว่านั้น) เชื่อมการดูแลเข้ากับเงินโดยตรง
- สัตว์แก่ตายได้ (ไก่ 3–4 ปี, แกะ 3–5 ปี, วัว 8–10 ปี) และมีการตั้งท้อง/เกิดลูก

**ยังไม่ได้ศึกษา** (ต้องอ่านโค้ดเพิ่มถ้าอยากได้กฎจริง):

| ระบบ | คำถามที่อยากรู้ |
| --- | --- |
| ร้านค้าและอัปเกรด | ราคา อัปเกรดเครื่องมือใช้อะไร ต่อเติมบ้านใช้ไม้เท่าไร ความเร็วที่เงินเข้า |
| เทศกาล | 14 วันต่อปี มีการแข่งขันอะไรบ้าง ตัดสินผลอย่างไร |
| ความรักและแต่งงาน | เกณฑ์หัวใจ heart event เงื่อนไขขอแต่งงาน ชีวิตหลังแต่ง |
| ฉากจบ | ประเมินผลผู้เล่นจากค่าอะไรบ้าง |

**ข้อเสนอสำหรับเกมของเรา**:

1. เริ่มจากวงจรหลักก่อน: เวลา → ฟาร์ม → ส่งขาย → นอน ให้สนุกด้วยตัวเองก่อนเพิ่มชาวบ้านและสัตว์
2. ทำทุกอย่างเป็น data-driven (พืช ไอเท็ม ตารางเวลา อากาศ ของขวัญ event) เหมือน HM จะปรับสมดุลและเพิ่มเนื้อหาได้เร็ว
3. จุดที่ HM น่ารำคาญและควรปรับ: รดน้ำทีละช่องทุกวัน พืชตายทันทีเมื่อเปลี่ยนฤดู และการต้องเดินไปกล่องส่งของทุกรอบ (ตะกร้าช่วยได้บางส่วน)
4. ความเสี่ยงที่ทำให้เกมมีชีวิต (พายุ สัตว์ป่วย การล้ม) ควรเก็บไว้ แต่ต้องเห็นล่วงหน้าและกู้คืนได้ ไม่ลงโทษแบบถาวร
